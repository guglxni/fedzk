QUALITY — Production OSS & CI Bars

Definition of “production-grade open source” for FEDzk. Aligns with quality-gates/config.yaml intent but grounded in runnable truth.

Quality means the concept is real: goldens prove L is enforceable; docs smoke proves the SDK matches CONCEPTS; forbidding mock proofs protects fail-closed (P2). Principles

1. Release gates (must all pass)

GateCheck
InstallClean VM: pip/uv install; fedzk doctor OK
CLIfedzk --help; from fedzk.cli import app (no package shadow)
Prove smokeQuantized N_dev vector: generate + verify OK
CryptoAll goldens verify; no mocks on default path
TestsCI green; critical coverage ≥90% on prover/coordinator/quantizer
Securitygitleaks clean; no tracked secrets; bandit high=0; cargo-audit OK
DocsEvery getting-started command in CI smoke
Supply chainSBOM + lockfiles; pinned actions SHA
LicenseLICENSE matches pyproject; third-party notices
VersionSingle version source; CHANGELOG; CITATION.cff

2. CI pipeline (target)

lint (ruff/mypy) → unit → golden-zk (artifact cache) →
integration (compose) → rust-cross-verify →
docs-smoke → security-scan → build-wheel

3. Quality gates file

Repo has quality-gates/config.yaml. Agents must reconcile fantasy thresholds (e.g. prove < 2s) with measured N:

  • Either raise thresholds to measured SLOs, or
  • Keep aspirational targets labeled aspirational: separate from enforced:.

4. OSS community hygiene

  • CONTRIBUTING.md matching real workflow.
  • CODE_OF_CONDUCT.md; SECURITY.md with disclosure email.
  • Issue templates: bug, circuit, experiment.
  • Good first issues after Phase 0.
  • CODEOWNERS for src/fedzk/zk/ and crates/.

5. Semantic versioning policy

  • MAJOR: proof schema break, circuit public-input break, remove backend.
  • MINOR: new circuits, Flower adapter, Rust engine stable.
  • PATCH: bugfixes, docs.

6. Honesty policy (non-optional)

README badges claiming “Production Ready”, “100% Tested”, “Enterprise Deployed” are forbidden until Release gates pass and a human maintainer signs the release checklist.

7. Mapping from prior review

  • Graph hubs → prioritize tests on ZKProver/Verifier/MPC/Coordinator.
  • Compliance modules → lint-only until core gates green.
  • Hybrid stack → CI matrix includes snarkjs and rust backends.

8. Release checklist (human)

  1. Phase 0–5 exit criteria in PLAN.html checked.
  2. Paper transcripts frozen & hashed.
  3. Ceremony/dev-key warnings audited in docs.
  4. Tag v1.0.0; publish; Zenodo; announce.
