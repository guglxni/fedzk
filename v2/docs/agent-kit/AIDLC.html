# Agents: use ROSTER.html + AIDLC.html + LOOPS.html instead of core/agents/*.md

1. Why AI-DLC for FEDzk

  • FEDzk is brownfield + dual mission (paper + OSS) — ad-hoc prompting drifts; gated stages keep crypto honesty.
  • 14-agent roster maps cleanly onto FEDzk domains (product, architect, developer, quality, devsecops, compliance…).
  • Learning loop captures corrections into rules/project.html.
  • Swarm/construction autonomy fits Phase 0 parallel hygiene units after walking skeleton.

3. Full stage checklist (FEDzk-adapted)

Initialization (always)

  1. 0.1 Workspace scaffold → intent record dir
  2. 0.2 Workspace detection → brownfield Python/Circom/Rust signals
  3. 0.3 State init → intent HTML + audit

Ideation (mvp-reduced)

  1. 1.1 Intent capture → dual mission locked
  2. 1.3 Feasibility → N, quantization, hybrid stack risks
  3. 1.4 Scope definition → AIDLC scope=mvp, depth=comprehensive crypto
  4. 1.7 Approval handoff → human-proxy OK for docs; user for releases

Inception

  1. 2.1 Reverse engineering → code truth vs README (done in prior review; refresh each major loop)
  2. 2.2 Practices discovery → mob: quality + developer + devsecops
  3. 2.3 Requirements analysis → REQUIREMENTS IDs
  4. 2.4 Application design → architecture.html + CONCEPTS invariant
  5. 2.5 User stories → researcher / FL eng / security eng
  6. 2.6 Units generation → Bolt DAG
  7. 2.7 Delivery planning → PLAN.html sequencing

Construction (per unit / bolt)

  1. 3.x Functional + NFR design for unit
  2. 3.x Code generation
  3. 3.x Build and test (+ goldens if crypto)
  4. 3.x CI pipeline updates
