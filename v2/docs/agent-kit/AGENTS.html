1. Mission

Transform FEDzk from a research-demo scaffold into:

  1. A production-grade open-source framework for ZK-verified federated learning.
  2. A reproducible research platform capable of supporting a peer-reviewed paper.

Both missions share one codebase. Marketing language that contradicts runnable code is a defect.

3. Non-negotiables

  • No mock proofs in production paths. Fail loud if toolchain/artifacts/inputs invalid.
  • No silent truncation of model parameters without explicit config + logged warning + paper-visible limitation.
  • Public API must match docs. If you change an export, update getting_started and examples in the same PR.
  • Never commit secrets. Remove tracked secrets/; use env / secret managers.
  • Proof wire format is a versioned contract (fedzk.proof.v1): snarkjs-compatible Groth16 JSON unless a major version bump.
  • Quantization is mandatory on the prove path for float tensors (field elements are integers).
  • Graphify after structural code changes when available: graphify update .
  • Prefer small, verified PRs with golden crypto tests over large speculative rewrites.

5. Standard workflow per task

  1. Boot: MANIFEST.html role load set only (do not preload entire kit).
  2. Orient: Read listed HTML pages + graphify query if graph exists.
  3. Spec: Confirm requirement ID from REQUIREMENTS / PLAN phase.
  4. Upstream: If integrating a library, follow REPOS.html (gh repo clone) — never invent URLs.
  5. Implement: Minimal change; keep wire formats stable.
  6. Verify: Unit + golden ZK test if crypto touched; example script if API touched.
  7. Document: Update the same PR’s kit HTML / code docs; remove false claims.
  8. Graph: graphify update . after code changes.

6. Stack policy (locked)

Hybrid is the default: Python (PyTorch FL) + Circom (circuits) + Rust (prove/verify hot path). Full Rust rewrite and circuit-system migration (Noir/Halo2) are opt-in strategies, not default. See STACK.html.

7. Communication rules

  • When reporting status, separate works today vs target.
  • Never claim “production-ready” until QUALITY.html exit gates pass.
  • Cite file paths and line-level evidence for crypto/security claims.
  • Prefer linking to this kit over inventing new process docs.

8. Forbidden

  • Loading vendor/aidlc-workflows/core/**/*.md (or any upstream AIDLC Markdown) as FEDzk agent instructions.
  • Writing stage contributions as Markdown under aidlc/ — use v2/docs/agent-kit/intents/.../*.html.
  • Adding mock proof generators “for CI convenience” on default paths.
  • Expanding compliance theater while core prove path remains broken.
  • Checking in .zkey for large production ceremonies without documenting trusted setup.
  • Using unverified GitHub URLs — always gh repo view owner/name first.
