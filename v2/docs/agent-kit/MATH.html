MATH — Formal Background for FEDzk

Mathematics agents must respect when implementing circuits, quantization, aggregation, and writing the paper. Inspired by FL + zkSNARK literature (see RESEARCH.html).

How MATH serves CONCEPTS: FedAvg is the learning concept; L_secure is the integrity concept; quantization is the encoding concept; Groth16 is the proof-system concept. Implement equations only as they support those roles— CONCEPTS.html.

Why these mathematical objects

  • FedAvg weights n_k/n: preserves standard FL comparability for the paper.
  • Squared norm in-circuit: avoids costly sqrt; matches common clipping practice.
  • Commitment binding in chunks: prevents mix-and-match proofs across rounds/clients.
  • Public vs private signals: design which parts of the statement are revealed—core product privacy posture.

1. Federated averaging (FedAvg)

With K clients, local datasets D_k, local steps producing weights w_k^{t+1} from global w^t:

w^{t+1} = Σ_{k=1..K} (n_k / n) · w_k^{t+1}    where n = Σ n_k

Equivalently on updates Δ_k = w_k^{t+1} − w^t:

w^{t+1} = w^t + Σ_{k=1..K} (n_k / n) · Δ_k

FEDzk inserts a verify predicate V(π_k, x_k)=1 before accepting Δ_k (or quantized form) into the sum.

2. Threat model (client integrity)

  • Malicious client may send arbitrary Δ to poison the global model.
  • Defense (this framework): prove Δ ∈ L for a language L defined by circuit constraints (norm bounds, sparsity, etc.).
  • Does not by itself prevent all poisoning (e.g. in-bound adversarial directions). Paper must be precise.

3. Fixed-point quantization

Field elements of BN254 scalar field F_r are integers mod r. Floats g ∈ ℝ^d map via scale s=2^{b}:

ĝ_i = clip(round(g_i · s), -M, M) ∈ ℤ

Require |ĝ_i| < r and typically |ĝ_i| ≪ r. Dequantize for aggregation display: g̃_i = ĝ_i / s.

Implementation law: Never pass Python floats into Circom/snarkjs witness generation. Quantization error ε_q must be measured in experiments (accuracy vs plaintext FL).

4. Example secure-update language

For quantized vector ĝ ∈ ℤ^N:

L_secure = { ĝ | Σ_i ĝ_i² ≤ B ∧ Σ_i 1[ĝ_i ≠ 0] ≥ m }

Circuit computes S = Σ ĝ_i² and nnz, enforces comparisons (LessThan gadgets from circomlib).

5. Rank-1 Constraint System (R1CS)

Circom compiles to R1CS: for witness z ∈ F^m, matrices A,B,C:

(Az) ∘ (Bz) = Cz

Public inputs are a subset of z; private signals are the rest (gradients may be private; bounds/public flags public — design choice documented per circuit).

6. Groth16 (intuition for engineers)

Groth16 (Groth, EUROCRYPT 2016) yields proofs π of constant size (3 group elements) for R1CS satisfiability, with pairing-based verification.

  • Setup: toxic waste → proving key pk, verification key vk.
  • Prove: π ← Prove(pk, x, w) for public x, witness w.
  • Verify: {0,1} ← Verify(vk, x, π).
  • Properties: completeness, knowledge soundness, zero-knowledge (under assumptions).

Curve in stack: BN254 / BN128 as used by snarkjs (curve: bn128 in proof JSON).

7. Why proof size / verify matter in FL

  • Each round, up to K proofs arrive; verify must be cheap relative to training.
  • Prove is client-side cost; paper reports wall-clock vs local epoch time.
  • Batch verification (same vk, many proofs) can amortize pairings — circuit/tooling dependent.

8. Differential privacy (optional circuit path)

Gaussian mechanism on clipped gradients:

g̃ = clip(g, C) + N(0, σ²C² I)

ZK can prove clipping / noise sampling constraints depending on circuit design — non-trivial; treat DP circuits as P1 and cite DP literature separately from ZK soundness.

9. Chunking math

For dimension d and circuit width N: k = ⌈d/N⌉ chunks. Commitment binding:

h = H(ĝ_1 ‖ ĝ_2 ‖ … ‖ ĝ_d ‖ round_id)

Each chunk proof includes (h, i, k) as public inputs to prevent mix-and-match attacks across clients/rounds.

10. Aggregation after ZK

Only updates with Verify=1 enter FedAvg. Optional robust aggregators (trimmed mean, Krum) are orthogonal post-verify layers — future work.
