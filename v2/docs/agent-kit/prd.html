Product Requirements Document — Contribution-Grade FEDzk

Target PRD for a research-publishable, production-grade open-source ZK-FL framework. Supersedes aspirational claims in the legacy README.

Version target: 1.0.0 OSS Legacy repo ≈ 0.3 research demo
Conceptual primer: This PRD operationalizes the FEDzk concept: integrity-gated FL with client-side ZK proofs of update constraint satisfaction. Non-goals (aggregator ZK, full train proofs, update-hiding) are intentional—see CONCEPTS §3.

Product concepts the PRD assumes

  • Integrity policy as product surface: users choose circuit_id / bounds like they choose optimizers.
  • Proof as admission ticket: UX and API center on prove→submit→verify, not on mock-friendly demos.
  • Reproducibility as a feature: experiment configs are first-class because FEDzk is also a research instrument.
  • Honesty as quality: claiming production without instantiating CONCEPTS is a product defect.

1. Vision

Enable practitioners and researchers to run federated learning rounds where each client proves—in zero knowledge—that its update satisfies publicly agreed constraints, and the coordinator rejects invalid updates with cryptographic certainty.

2. Problem

  • Plain FL trusts clients; Byzantine / poisoning attacks are real.
  • Existing ZK-FL research often lacks open, reproducible frameworks.
  • Current FEDzk scaffolding overclaims readiness (n=4 toy circuits, broken packaging).

4. Non-goals (v1)

  • Full on-chain settlement / blockchain dependency (optional later).
  • Replacing PyTorch with Rust training.
  • Migrating all circuits to Noir/Halo2 in v1.
  • Enterprise compliance theater (GDPR PDF generators) as a substitute for crypto correctness.
  • Supporting 10M-parameter end-to-end single-circuit proofs without chunking (must be explicit chunk protocol).

5. Personas

  • Researcher: runs experiment YAMLs, exports transcripts, cites framework.
  • FL engineer: integrates LocalTrainer + prove into existing pipeline.
  • Security engineer: audits circuits, trusted setup, threat model.
  • OSS contributor: clear issues, good-first-issues, passing CI.

6. User stories

  • As a researcher, I can reproduce Adult LR FEDzk vs baseline accuracy within ε from published transcript.
  • As a developer, I can pip install -e ., run setup script, and complete one local prove→verify→aggregate demo in <30 minutes on a laptop.
  • As a coordinator operator, I can reject malformed/out-of-bound updates with logged proof failures.
  • As a contributor, I can add a circuit variant with golden tests via documented template.

7. Functional requirements (summary)

Full list in REQUIREMENTS.html. Must-have for v1:

  • FR-1 Quantized gradient prove/verify (parameterized N).
  • FR-2 Secure circuit: L2 bound + min nonzero.
  • FR-3 Coordinator verify-before-FedAvg.
  • FR-4 MPC remote prove optional.
  • FR-5 CLI: setup, prove, verify, train-round, mpc serve.
  • FR-6 Experiment runner + transcript schema.
  • FR-7 Batch verification path (paper + CIFAR config).

8. Success = Definition of Done (v1.0)

  • QUALITY.html gates green on main.
  • Paper experiment matrix runnable from clean machine instructions.
  • PyPI or GitHub Release with signed artifacts + SBOM.
  • Security: zero criticals; secrets untracked; prod mode refuses default keys.
  • Docs site / agent-kit + human docs agree with API.
