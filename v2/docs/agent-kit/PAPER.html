PAPER — Research Paper Plan

Working outline for a systems/security + FL venue paper backed by the open framework.

Measured on branch v2 (2026-07-22, synthetic Adult): Attack suite reject rate 1.0 (5/5). E5 verify p50: snarkjs ~180ms vs rust ~74ms (N=4 golden). Tables: artifacts/paper/metrics-tables.md. Ceremony for N=64/256 remains dev_unsafe — do not claim production setup.

Working title options

  • FEDzk: An Open Framework for Zero-Knowledge Verified Federated Model Updates
  • Client-Side zkSNARKs for Integrity-Constrained Federated Learning: System and Evaluation

Claim checklist (only claim what experiments show)

  • C1: Framework proves quantized updates satisfy circuit constraints under Groth16.
  • C2: Coordinator rejects malformed / out-of-bound updates with measured false accept ≈ 0 on suite.
  • C3: Accuracy vs plaintext FL within reported gap on Adult / CIFAR settings.
  • C4: End-to-end overhead (prove/verify/network) characterized vs round time.
  • C5: Open artifacts enable reproduction (configs, transcripts, circuit hashes).

Suggested structure

  1. Introduction — FL trust gap; client integrity; contributions.
  2. Background — FedAvg, R1CS, Groth16, quantization (MATH.html).
  3. Threat model — malicious clients; honest-but-curious server; non-goals.
  4. System design — architecture, circuits, chunk protocol, engines.
  5. Implementation — Python FL, Circom, Rust/snarkjs, lines of code, artifact pipeline.
  6. Evaluation — setup; datasets; metrics; results; attacks; ablations.
  7. Related work — zkFL, zkFDL, Federify, Flower, etc.
  8. Discussion — limitations, ethics, trusted setup.
  9. Conclusion
